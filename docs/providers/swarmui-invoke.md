# SwarmUI and InvokeAI (local servers) — brief assessment

- Website / docs: SwarmUI https://github.com/mcmonkeyprojects/SwarmUI/blob/master/docs/API.md (+ `docs/APIRoutes/T2IAPI.md`, `BasicAPIFeatures.md`, `ModelsAPI.md`, `docs/Sharing Your Swarm.md`, `docs/Advanced Usage.md`) · InvokeAI https://github.com/invoke-ai/InvokeAI (source `invokeai/app/api_app.py`, `invokeai/app/api/routers/session_queue.py`, `images.py`, `invokeai/app/services/config/config_default.py`, `invokeai/app/services/session_queue/session_queue_common.py`; docs `docs/src/content/docs/configuration/invokeai-yaml.mdx`; live OpenAPI at `http://127.0.0.1:9090/docs`)
- Last verified: 2026-09-06 (repo docs and source on default branches; invoke-ai.github.io was not reachable from the sandbox so InvokeAI facts come from source + the docs source tree; re-verify before shipping)
- Adapter ids: `swarmui`, `invokeai`  ·  Transport: `direct`  ·  Priority wave: **3 (SwarmUI: consider) / skip (InvokeAI)** — see Recommendation

## Recommendation
- **SwarmUI: support in wave 3 as a lightweight "simple generate" adapter, if at all.** Pros: a real documented JSON API with a flat parameter map (`prompt`, `model`, `width`, `height`, `steps`, `cfgscale`, `seed`, `initimage`, …), `GetNewSession` needs no account on a default install, `ListModels`/`ListT2IParams` give discovery, and it fronts ComfyUI so it covers video models. Cons: (1) **no documented CORS setting** — SwarmUI is an ASP.NET app and its docs never mention `Access-Control-Allow-Origin`; cross-origin browser calls from `https://www.thewoovee.com` are therefore **unverified/likely blocked** without a reverse proxy adding CORS headers; (2) when the instance requires accounts, auth is a `swarm_token` **cookie** (docs/API.md), which a cross-origin browser client cannot set; (3) `GenerateText2Image` over plain HTTP is synchronous (the WS variant is the recommended one), which collides with the Cloudflare 125 s read timeout for remote use. Most SwarmUI users also have ComfyUI reachable (`/ComfyBackendDirect/*` pass-through exists), so the ComfyUI adapter already serves them.
- **InvokeAI: skip.** The public surface is a graph/queue API designed for its own frontend: you must build a full invocation `graph` (node dicts with typed edges — the equivalent of a ComfyUI API workflow but with less documentation and frequent schema churn), enqueue it, follow Socket.IO events, then fetch images by name. CORS is configurable (`allow_origins` in `invokeai.yaml`), which is good, but the effort/benefit is poor relative to ComfyUI which the same users can run. Revisit only if user demand appears.

## SwarmUI — essentials
### Account and authentication
- Default `http://localhost:7801` (docs/API.md examples). Bind address via Server → Server Configuration → `Host` = `0.0.0.0` (docs/Advanced Usage.md); not needed for tunnel use.
- Session, not key: `POST /API/GetNewSession` with body `{}` → `{"session_id": "...", "user_id": "local", "output_append_user": true, "version": "0.6.3.0.GIT-…", "server_id": "...", "permissions": [...]}` (BasicAPIFeatures.md). Every other call must include `"session_id"` in its JSON body. Errors come back as `{"error": "...", "error_id": "invalid_session_id"}` → call `GetNewSession` again.
- If `AuthorizationRequired` is enabled (Server Configuration → User Authorization; `AllowLocalhostBypass` optional), requests must carry a `swarm_token` cookie created in the UI's User tab ("Swarm Auth Tokens") (docs/API.md). There is also `POST /API/Login` / `Logout`. Multi-user is "initial experimental" and the docs say not to expose publicly without an auth layer (Advanced Usage.md) — i.e. Cloudflare Access.
### Browser (CORS) behaviour
- **Unverified.** No CORS option is documented in `docs/`; assume browser cross-origin calls fail unless a proxy adds headers. (Cloudflare Access "configure response to preflight" cannot add CORS headers to non-OPTIONS responses, so it does not solve this.) This is the main blocker.
### Endpoints (exact)
- `POST /API/GenerateText2Image` — body is the **root map**: `{"session_id": "...", "images": 1, "prompt": "a cat", "negativeprompt": "", "model": "OfficialStableDiffusion/sd_xl_base_1.0", "width": 1024, "height": 1024, "steps": 20, "cfgscale": 7.5, "seed": -1, "donotsave": true, ...}` (`images` and `rawInput` documented as required; in practice T2I params sit at root level next to `session_id`). Response `{"images": ["View/local/raw/2024-05-19/<file>.png", ...]}` (paths relative to the server root; "in some cases can be a 'data:...' encoded image"). Fetch with `GET http://host:7801/View/local/raw/...`. Sync HTTP.
- `WS /API/GenerateText2ImageWS` — same input; streams `{"status": {...}}`, `{"gen_progress": {"batch_index", "overall_percent", "current_percent", "preview": "data:image/jpeg;base64,..."}}`, `{"image": {"image": "View/...", "batch_index", "metadata"}}`, `{"discard_indices": [...]}`. "The most important route inside of Swarm."
- Other params (from the T2I parameter list; discover with `POST /API/ListT2IParams` → `list[]` of `{name,id,type,default,min,max,step,values,...}` plus `models` and `wildcards`): `initimage` (data URL), `initimagecreativity`, `maskimage`, `sampler`, `scheduler`, `videomodel`, `videoframes`, `videofps` etc. Names are the lowercase `id`s from `ListT2IParams`.
- `POST /API/ListModels {"session_id", "path": "", "depth": 2, "subtype": "Stable-Diffusion"}` → `{"folders": [...], "files": [{"name", "title", "architecture", "class", "resolution", "preview_image", ...}]}`; `POST /API/SelectModel`; `POST /API/InterruptAll {"other_sessions": false}`; `POST /API/ListImages {"path": "", "depth": 1}`; `POST /API/DeleteImage {"path"}`.
- Output: files under the user's output folder served at `/View/<user>/raw/<yyyy-mm-dd>/<file>` (docs/API.md).
### Gotchas
- Session ids expire/are invalidated on restart; wrap every call with a retry on `invalid_session_id`.
- Default install ships with a bundled ComfyUI backend; for power users the ComfyUI adapter is the better integration point.

## InvokeAI — essentials
### Account and authentication
- Default `http://127.0.0.1:9090` (`host: 127.0.0.1`, `port: 9090` in `config_default.py`); set `host: 0.0.0.0` in `invokeai.yaml` for LAN. Swagger UI at `GET /docs`, schema `GET /openapi.json`.
- `multiuser: false` by default ("runs in single-user mode using a default system account with administrator privileges"); when `true` it requires login (`POST /api/v1/auth/login`, Bearer JWT with sliding expiry via the `X-Refreshed-Token` response header — `api_app.py`).
### Browser (CORS) behaviour
- Configurable: `invokeai.yaml` keys `allow_origins: []` (default empty → nothing allowed), `allow_credentials: true`, `allow_methods: ["*"]`, `allow_headers: ["*"]` (`config_default.py`), applied via FastAPI `CORSMiddleware` (`api_app.py`, `expose_headers=["X-Refreshed-Token"]`). A user would add `allow_origins: ["https://www.thewoovee.com"]`. Not tested live.
### Endpoints (exact)
- `POST /api/v1/queue/{queue_id}/enqueue_batch` (queue_id is `default`) body `{"batch": {"batch_id"?: "...", "origin"?: null, "destination"?: null, "data"?: [[{"node_path","field_name","items":[...]}]], "graph": {"id": "...", "nodes": {"<id>": {"id","type":"<invocation type>", ...fields}}, "edges": [{"source": {"node_id","field"}, "destination": {"node_id","field"}}]}, "workflow"?: {...}, "runs": 1}, "prepend": false}` → 201 `EnqueueBatchResult {"queue_id", "enqueued", "requested", "batch", "priority", "item_ids": [int]}` (`session_queue.py`, `session_queue_common.py`).
- Status/polling: `GET /api/v1/queue/{queue_id}/status`, `GET /api/v1/queue/{queue_id}/b/{batch_id}/status`, `GET /api/v1/queue/{queue_id}/i/{item_id}` (item has `status`: `pending|in_progress|completed|failed|canceled`, `session` with `results`), `PUT /api/v1/queue/{queue_id}/i/{item_id}/cancel`, `PUT /api/v1/queue/{queue_id}/cancel_by_batch_ids`, `PUT .../clear`, `.../prune`, `GET .../current`, `GET .../list_all`. Real-time events are Socket.IO (`invokeai/app/api/sockets.py`), not plain WS.
- Images: `POST /api/v1/images/upload` (multipart `file`, query `image_category=user&is_intermediate=false[&board_id=]`) → `ImageDTO {"image_name", "image_url", "thumbnail_url", "width", "height", ...}`; `GET /api/v1/images/i/{image_name}/full` (PNG), `/thumbnail`, `/metadata`, `/urls`; `GET /api/v1/images/` (list); `DELETE /api/v1/images/i/{image_name}`.
- Model discovery: `GET /api/v2/models/` (model manager v2) — shape not verified this session.
### Gotchas
- The `graph` must reference concrete invocation types (`main_model_loader`, `compel`, `noise`, `denoise_latents`, `l2i`, …) whose fields change between releases; the only reliable schema is the running server's `/openapi.json`. The practical way to get a graph is to capture the frontend's `enqueue_batch` payload in devtools.
- Generated images are stored in the gallery DB; results appear as image names inside the queue item's `session.results`.
