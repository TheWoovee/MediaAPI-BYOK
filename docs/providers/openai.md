## Account and authentication
- Get a key: https://platform.openai.com → API keys (https://platform.openai.com/api-keys). Paid, prepaid credits; no free credits for new orgs are documented. Some image models historically required organization verification (https://platform.openai.com/settings/organization/general) — current requirement for gpt-image-2 is unverified.
- Auth header: `Authorization: Bearer <OPENAI_API_KEY>`; optional `OpenAI-Organization: org_...` and `OpenAI-Project: proj_...`.
- Base URL: `https://api.openai.com/v1`. Data residency is per-project (`PublicProjectResidency` enum in the spec: GLOBAL, US_STORAGE_PROCESSING, EU_STORAGE_PROCESSING, …); the URL does not change.

## Browser (CORS) behaviour
- Result: **unknown from this environment**. The preflight `OPTIONS https://api.openai.com/v1/images/generations` with `Origin: https://www.thewoovee.com` was refused by the sandbox egress proxy (`403 Forbidden` from the proxy). Re-run the curl from a real network before deciding transport.
- Browser story per OpenAI: the official `openai` npm SDK refuses to run in a browser unless `new OpenAI({ apiKey, dangerouslyAllowBrowser: true })` — README: "Web browsers: disabled by default to avoid exposing your secret API credentials. Enable browser support by explicitly setting `dangerouslyAllowBrowser` to `true`." (https://github.com/openai/openai-node/blob/master/README.md). The option's existence implies browser calls are technically served, but community threads also report `No 'Access-Control-Allow-Origin'` failures for some flows (https://community.openai.com/t/how-to-fix-cors-policy-error-when-fetching-openai-api-from-localhost/1140420). DALL-E result URLs on `oaidalleapiprodscus.blob.core.windows.net` are reported to lack CORS headers (https://community.openai.com/t/access-to-an-image-created-with-dall-e-blocked-by-cors-policy-no-access-control-allow-origin-header-is-present-on-the-requested-resource/876625). Treat as `proxy` unless the live preflight test passes.

## Endpoints (exact)
### POST https://api.openai.com/v1/images/generations — sync (optionally SSE stream)
JSON: `{"model":"gpt-image-1.5","prompt":"A cute baby sea otter","n":1,"size":"1024x1024"}`.
Optional: `quality` (`auto` default; `low|medium|high` GPT; `standard|hd` dall-e-3), `size` (see table; default `auto` for GPT, `1024x1024` dall-e), `background` `transparent|opaque|auto`, `output_format` `png|jpeg|webp` (default png), `output_compression` 0–100 (default 100, jpeg/webp only), `moderation` `low|auto`, `stream` bool, `partial_images` 0–3, `response_format` `url|b64_json` (dall-e only; GPT models always return base64), `style` (dall-e-3), `user`.
Response (`ImagesResponse`): `{"created":1713833628,"data":[{"b64_json":"..."}],"background":"opaque","output_format":"png","size":"1024x1024","quality":"high","usage":{"total_tokens":100,"input_tokens":50,"output_tokens":50,"input_tokens_details":{"text_tokens":10,"image_tokens":40}}}`. For dall-e with `response_format:"url"`: `data[].url` (valid 60 minutes) and `data[].revised_prompt` (dall-e-3). Streaming: `text/event-stream` with `image_generation.partial_image` / `image_generation.completed` events carrying `b64_json`.
Errors: 429 (`InferenceRateLimited`), 503.

### POST https://api.openai.com/v1/images/edits — sync (optionally stream)
Two encodings:
- `multipart/form-data`: fields `image` (file, or `image[]` repeated up to 16), `prompt`, optional `mask` (PNG <4 MB, same dimensions as first image, transparent = editable), `model`, `n`, `size`, `quality`, `background`, `output_format`, `output_compression`, `input_fidelity` (`high|low`, default low; not for `gpt-image-1-mini`), `stream`, `partial_images`, `user`.
- `application/json` (`EditImageBodyJsonParam`, GPT models only): `{"model":"gpt-image-1.5","prompt":"Add a watercolor effect","images":[{"image_url":"https://example.com/source.png"}],"size":"1024x1024","quality":"high"}` where each `images[]` item is `{"image_url": "<https URL or data: URL (≤20 MB)>"}` or `{"file_id":"file-123"}`; optional `mask` uses the same ref shape; `n`, `quality`, `input_fidelity`, `background`, `output_format`, `output_compression`, `stream`, `partial_images`.
Response: same `ImagesResponse` (base64).

### POST https://api.openai.com/v1/images/variations — dall-e-2 only, multipart. Not worth wrapping.

### Videos API (all `deprecated: true`, shutdown 2026-09-24)
- `POST /v1/videos` — async. multipart or JSON: `{"model":"sora-2","prompt":"A calico cat playing a piano on stage","seconds":"8","size":"1280x720","input_reference":{"image_url":"data:image/png;base64,..."}}` (`input_reference` = `{image_url}` | `{file_id}`, or a binary file field in multipart; image must match the target `size`). Returns a `VideoResource` immediately.
- `GET /v1/videos/{video_id}` — poll. `VideoResource`: `{"id":"video_123","object":"video","model":"sora-2","status":"queued"|"in_progress"|"completed"|"failed","progress":0-100,"created_at":…, "completed_at":null,"expires_at":…, "prompt":"…","size":"1280x720","seconds":"8","remixed_from_video_id":null,"error":{"code":"…","message":"…"}|null}`.
- `GET /v1/videos/{video_id}/content?variant=video|thumbnail|spritesheet` — bytes (`video/mp4` or `image/webp`), only after `completed`, until `expires_at`.
- `POST /v1/videos/{video_id}/remix` `{"prompt":"…"}`; `POST /v1/videos/edits` `{"video":{"id":"video_123"},"prompt":"…"}`; `POST /v1/videos/extensions` `{"video":{"id":"video_123"},"prompt":"…","seconds":"4"|"8"|"12"|"16"|"20"}` (extension segment length; `seconds` on the result is the stitched total); `GET /v1/videos` (list), `DELETE /v1/videos/{id}`; `POST /v1/videos/characters` (multipart video + name).
- Polling interval: guide suggests a few seconds; webhooks exist for video completion events (event names unverified). No cancel endpoint.

## Input media
- Images API: multipart binary upload, or JSON `image_url` (https URL **or** base64 data URL, spec `maxLength: 20971520` ≈ 20 MB) or Files API `file_id`. GPT models: png/webp/jpg, <50 MB each, ≤16 images; dall-e-2: one square png <4 MB. Mask: PNG <4 MB, same size as first image.
- Videos API: `input_reference` image (jpg/png/webp; must match `size`), or an API-generated `video.id` for remix/edit/extend (no arbitrary video upload for extend/edit per spec — `VideoReferenceInputParam` is `{id}`; multipart variants also accept a binary file).

## Output media
- Images: GPT image models **always** return `b64_json` (no URL option) — ideal for a browser app, no CORS issue. DALL-E: `url` (60-minute expiry, Azure blob host without CORS headers per community reports) or `b64_json`.
- Videos: bytes via `/v1/videos/{id}/content` (needs the bearer header → must go through the proxy; not a plain URL), until `expires_at`.

## Rate limits, quotas, free tier
- Images per minute (IPM) and RPM limits are per organization tier; the exact current tables are on the model cards (unverified here). 429 → `InferenceRateLimited`.
- No free tier for image/video generation.

## Gotchas
- **Videos API disappears on 2026-09-24** (18 days after this research). Do not invest in a Sora adapter; if built, gate it behind a date check and expect 404/410 afterwards.
- `model` default on `/v1/images/generations` is `dall-e-2` unless a GPT-only param is present — always send `model` explicitly.
- `response_format` is rejected/ignored for GPT image models; `size:"auto"` is only for models that allow it.
- `gpt-image-2` arbitrary sizes: enforce divisible-by-16 and 1:3–3:1 client-side; >2560x1440 is experimental.
- `background:"transparent"` requires `output_format` png or webp.
- `input_fidelity:"high"` is unsupported on `gpt-image-1-mini` (400).
- JSON edits accept data URLs up to ~20 MB per image; larger sources must use multipart or the Files API.
- `usage` token accounting differs per model (`ImageGenUsage` vs `ImagesUsage`); do not rely on it for exact cost.

## Adapter mapping notes
- text→image → `/v1/images/generations` (`model`, `prompt`, `size`, `quality`, `output_format`, optional `background`, `moderation`). Offer `gpt-image-2` (free-form size) and `gpt-image-1.5` / `gpt-image-1-mini` (fixed 3 sizes). Decode `b64_json` directly into a Blob.
- image edit / inpaint → `/v1/images/edits` as JSON with `images:[{image_url:"data:…"}]` and optional `mask:{image_url:"data:…"}` (alpha mask) — pure JSON through the proxy avoids multipart handling; fall back to multipart for >20 MB inputs. Expose `input_fidelity` toggle (hide for mini).
- Streaming previews: optional `stream:true, partial_images:1-3` over SSE if the proxy passes `text/event-stream` through.
- video: skip (deprecated). If the user insists: create → poll `GET /v1/videos/{id}` (3–5 s) → download `/content` through the proxy → store; remix/extend by `id`.
- Cost estimate: per-token image pricing; show the official calculator link rather than a hard-coded table until verified.
